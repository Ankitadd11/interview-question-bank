## Q1. Can you detail your experience with backend technologies like Nest.js, Node.js, and database management?

### Answer

In my role at Cybage, I utilized Nest.js, a Node.js framework, for building scalable backend services. Nest.js’s modular architecture and use of TypeScript help enforce strong typing and maintainable codebases, which enhances long-term project stability.
I have also worked extensively with Node.js for developing RESTful and GraphQL APIs that support high-concurrency environments typical in fintech domains.
Regarding database management, I have hands-on experience with both relational databases like MySQL, PostgreSQL, and NoSQL databases like MongoDB and Redis. I design schemas optimized for query performance and transactional integrity, particularly important for financial data.
My approach includes leveraging caching strategies with Redis to reduce database load and improve response times. I consider database scalability and replication to ensure fault tolerance and responsiveness globally.
Integration of backend with cloud storage and serverless components further enhances scalability, fault tolerance, and cost optimization, aligning well with Mastercard’s technology stack and high-availability demands.

Q3. Describe your experience designing and managing APIs using GraphQL and REST principles.

Ans: My API design experience is comprehensive and spans both REST and GraphQL paradigms. At Solace InfoTech, I developed GraphQL APIs using Node.js and AWS, optimizing data retrieval for complex client queries, significantly improving efficiency over traditional REST.
I focused on modular API schema design, ensuring that services remain loosely coupled and can evolve independently. This approach fits well with microservices architectures Mastercard champions.
REST principles guided my creation of straightforward HTTP endpoints following resource-based design, appropriate status codes, and stateless interactions, which are essential for resilience and scalability in financial platforms.
GraphQL allowed me to enable clients to specify exactly what data they need, reducing over-fetching and network load, thus enhancing performance, an important consideration in high-transaction-volume fintech systems.
I also incorporated security considerations such as authorization, authentication via JWT, input validation, and rate limiting in my API designs to meet stringent financial service requirements.
This blend of REST and GraphQL experience prepares me well to develop sophisticated, enterprise-grade APIs for Mastercard's Commercial Solutions platform, balancing flexibility, performance, and reliability.
